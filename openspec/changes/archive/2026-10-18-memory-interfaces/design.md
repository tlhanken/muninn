# Design — Memory Interfaces

## The problem is drift, not disagreement

The three copies of the format (vault `SCHEMA.md`, code, specs) did not start out
different; they drifted, because nothing connected them. Picking the right values once
would only reset the clock. The design therefore fixes *where* each format is defined and
adds a check that fails when a copy diverges.

## Decision D1: Code is the single source

All value sets live as named constants in `parser.py`:

| Constant | Meaning |
|---|---|
| `PAGE_TYPES` | types `wiki_write` accepts |
| `CONFIDENCE_LEVELS`, `DEFAULT_CONFIDENCE` | confidence values and the coercion target |
| `STATUSES`, `DEFAULT_STATUS` | status values and the coercion target |
| `SEARCH_EXCLUDED_STATUSES` | statuses hidden from search |
| `SESSION_LOG_*`, `SESSION_ENTRY_RE` | session-log directory, type, tags, fields, entry header |

`parser.py` was chosen over a new module because it is already the shared, path-loaded
module that both `__init__.py` and the Tier 1 tests load (see AGENTS.md); a new sibling
file would add a second path-loading contract to keep intact.

The session-log format moves with them as small helpers (`session_slug`,
`format_session_turn`, `create_session_log`, `count_session_entries`), so the provider
and the tests exercise the same code. `create_session_log` writes `agent` together with
the rest of the frontmatter instead of injecting it in a second rewrite of the file.

**Alternative considered:** a YAML schema file loaded at runtime. Rejected: it adds a
file-loading path and a parse step to every provider start, and the spec would still be
a second copy needing the same parity check.

## Decision D2: Spec lines are machine-checkable

Each value set appears in `openspec/specs/memory-interfaces/spec.md` on its own line,
`<Label>: `value`, `value`, …`. `tests/test_memory_interfaces_contract.py` (Tier 1, so
it runs in `nix flake check`) extracts those lines and compares them with the constants.
A change to either side alone fails the build.

## Decision D3: The type set

Adopt the vault's types: add `self-model` and `strategy`. Drop `dream-candidate` from the
writable set (no writer since `descope-dreaming`). Keep `note`: it is currently writable,
and removing it would start rejecting writes that work today for no gain. Reading never
rejects a type, so existing `dream-candidate` files still parse.

## Decision D4: Statuses and confidence are documented as implemented

The code already coerces unknown values (`status` → `active`, `confidence` → `medium`)
and hides `superseded`/`rejected` from search. These are documented as-is. `candidate`
stays in the status set although nothing writes it: dropping it would coerce existing
candidate pages to `active` and surface them in search.

## Decision D5: Session-log format as implemented

The implemented format is canonical: `type: episodic`, tags `session`, `log`,
`agent:<profile>`, an `agent` field, `summary` added at session end, and one
`### <timestamp> | <Speaker>` entry per speaker. The vault's richer "Session Summary"
fields (`participants`, `topics`, `open_items`) are not part of the raw log.

Truncation and the entry cap are owned by `session-log-uncapped`, not this change.

## Decision D6: The vault defers

`just schema-doc` prints the contract table from code. The vault's
`04 - AI/SCHEMA.md` replaces its own format definitions with this pointer (paste by hand;
the vault is outside this repo):

```markdown
## Page and session-log formats

Muninn defines these formats in code; this vault does not. The authoritative
definition is `openspec/specs/memory-interfaces/spec.md` in the Muninn repository.
The table below is generated by `just schema-doc` — regenerate it rather than
editing it, and treat any difference from the spec as a stale copy.

<paste the output of `just schema-doc` here>
```

## Risks / Trade-offs

- [Vault copy goes stale] → It is now labelled as generated and non-authoritative, so a
  stale copy is visibly a copy rather than a competing definition.
- [Parity test parses prose] → The label lines are a fixed format; the test fails loudly
  if a label disappears, so a reworded spec cannot silently skip the check.
- [`self-model`/`strategy` newly writable] → Additive; nothing that worked before breaks.
  The one rejection added is `dream-candidate`, whose only writer was descoped.
